# SO-101 Control Demo

SO-101 机械臂在 MuJoCo 中通过双 RGB 相机定位，将三个方块放入两个盒子。使用颜色/轮廓识别、几何定位、逆运动学和反馈状态机，不使用学习模型或训练数据。

## 运行

Python 3.11 或 3.12。在本目录安装依赖后启动：

```bash
python -m pip install -r requirements.txt
python run_demo.py
```

首次运行自动下载固定版本的 SO-101 物理模型，需要访问 GitHub；以后使用本地缓存。也可以使用已有模型：

```bash
python run_demo.py --model "D:/so101/models/robotstudio_so101/scene.xml"
```

默认按红、蓝、黄的顺序执行，红、黄放入绿色盒子，蓝放入紫色盒子。终端输出定位依据、各阶段和最终结果。`--headless` 不打开窗口，但视觉控制仍需要离屏渲染；无桌面的 Linux 可设置 `MUJOCO_GL=egl`。`--state-control` 显式切回原来的仿真坐标控制，仅用于对照；视觉失败不会自动切换。

## 双相机

启动后同时显示可自由旋转的三维窗口、夹爪相机 `wrist_cam` 和固定俯视相机 `overhead_cam`。夹爪相机沿用模型自带的安装位置，随手腕运动；俯视相机固定在基座坐标 `(0.18, 0, 0.45)` 米，垂直向下。关闭任一窗口，或在相机窗口按 Esc，结束仿真。

| 相机 | 默认图像 | 视场角近似 |
|---|---|---|
| 夹爪 GC0308 | 640×480 RGB | 120° 对角 |
| 俯视 GC2083 | 1920×1080 RGB，窗口缩小显示 | 暂按 160° 对角 |

默认预览最高约 15 fps，实际帧率取决于机器性能。`--camera-fps 5` 降低预览频率；`--no-cameras` 关闭 RGB 预览窗口，视觉定位仍会按需取图。坐标对照模式的俯视图默认为 960×540，`--camera-full-res` 可改为全分辨率。

商品参数没有注明 160° 的测量方向，也没有内参、畸变系数或实际安装位姿，因此目前是理想针孔 RGB 相机近似，不模拟鱼眼畸变、自动曝光、深度或真实帧率。广角下方块在俯视画面里会较小。视场角在 `control.py` 的 `CAMERAS` 中设置，再按画幅换算成 MuJoCo 的垂直视场角；实机标定后应替换这些参数和安装位姿。

## 视觉控制流程

1. **观察与定位**：机械臂让开俯视视线，从 RGB 检测三个方块和两个盒子。结合相机内参、位姿及已知平面高度，换算到基座坐标；连续三帧位置稳定后规划。
2. **靠近与确认**：按视觉坐标生成关节轨迹。到达上方及下降结束、闭爪之前，夹爪相机用同一时刻的图像和相机位姿，检查目标颜色区域是否出现在预期抓取区域；它不输出单目深度。
3. **抓放与反馈**：组合靠近、下降、夹紧、抬升、搬运、释放、撤离等阶段，按关节到位及夹持/承重反馈推进。放下后再次让开视线，连续观察一秒，确认物体在目标位置且受到支撑。
4. **失败处理**：定位阶段最多等待两秒；在目标上方确认不符时，最多重新观察并规划两次。下降结束后确认不符、搬运中丢失夹持、执行超时或重试耗尽时返回失败并阻止后续动作；单任务总预算为 100 秒仿真时间。

定位模块不读取物体/盒子的仿真位置、深度图或分割 ID。相机内参和安装位姿使用仿真模型；关节、夹爪接触和底部承重仍是仿真传感反馈。接口中的 `perception` 给出视觉坐标及图像时间戳，移动期间这些坐标只是最近一次观察，不是持续跟踪结果。

## 外部指令

先启动等待指令的模式，再在另一个终端发送任务：

```bash
python run_demo.py --manual
```

```bash
python send_command.py pick red_cube left_box --id task-1
python send_command.py status
```

接口为本机 `http://127.0.0.1:8765`。`POST /commands` 接收以下 JSON，`GET /status` 查询执行结果。提交成功只表示已入队，任务完成以 `SUCCESS` 为准。

```json
{"id":"task-1","action":"pick_place","object_id":"red_cube","target_id":"left_box"}
```

物体为 `red_cube`、`blue_cube`、`yellow_cube`；目标为 `left_box`（绿色，机器人 +Y 侧）或 `right_box`（紫色，−Y 侧）。

## 代码

- `control.py`：场景、逆运动学、抓放状态机和任务调度。检查到位、夹持、抬升、释放和落位反馈，再进入下一阶段。
- `run_demo.py`：模型下载、双相机 RGB 画面、本机 JSON 接口及仿真循环。接口接收任务，物理线程更新控制输入；执行结果通过同一任务 ID 返回。
- `send_command.py`：发送任务和查询状态的命令行客户端。
- `vision.py`：RGB 检测、平面坐标换算、夹爪视角确认及帧时效检查。
- `verify_vision.py`：随机摆位定位、完整抓放、目标移动重试、遮挡及无效图像测试。运行 `python verify_vision.py`。

采用“指令—持续执行—状态反馈”的控制流程。

## 当前范围

当前视觉基线限定为已知颜色、边长 3 cm 的直立方块和已知尺寸、轴对齐的盒子，位于指定桌面工作区。采用已知平面/尺寸约束恢复位置，不能测量未知高度或识别任意厨房物体；不含通用避障、行走或真机适配。帧率与颜色阈值、安装标定、遮挡情况都会影响结果。

物理模型来自 [MuJoCo Menagerie / robotstudio_so101](https://github.com/google-deepmind/mujoco_menagerie/tree/98a70c569c4c1b6da467a20012f766ee1f8dc521/robotstudio_so101)，下载时一并保留上游 LICENSE。运行时增加方块和盒子，并调整夹爪力矩限制。

## 真机复现

当前版本是仿真示例，尚未接入或验证 SO-101 真机。固定的是抓放流程；每次任务开始时从图像重新定位，再用逆运动学计算关节目标，并非回放一组固定关节角。

不要求使用完全相同的方块，但首次复现建议使用夹爪能够夹住的直立硬质方块，沿用从上方抓取的方式。更换尺寸后，需要调整抓取高度、夹爪开口、搬运高度和放置间距；杯子、碗或软物体需要另外设计抓点和姿态。

真机运行前还需完成：

- **硬件与校准**：接入电机通信，校准关节零位、方向、单位和限位，将关节目标映射到实际电机，并设置合适的速度与夹持力度。
- **图像与标定**：将渲染图像替换成真实相机图像，标定内参、畸变、固定相机到基座的变换和夹爪相机的手眼关系；同步图像与关节状态，按实际物体尺寸/桌面高度及光照调整定位参数。商品参数不能替代标定。
- **执行反馈**：用真机可获得的关节、夹爪反馈及必要的视觉确认，替换仿真的接触、抬升和落位判断。夹爪闭合不等于成功抓住物体。

首次真机验证可固定摆位并人工测量坐标，低速验证运动映射，再核对相机定位误差后接入视觉流程。上述真机适配尚未包含在本仓库中。
